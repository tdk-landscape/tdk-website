Examples & Reference Landscapes

Production-grade example repositories demonstrating the Project-Stack-Resource (PSR) model in action.

Official Reference Repositories

Clone and run these complete, battle-tested TDK landscapes locally with a single command via the TDK CLI:

terminal
tdk project example          # base reference stack
tdk project user-management  # enterprise governance demo
tdk project erp              # enterprise ERP system
tdk project restaurant       # restaurant ops demo
tdk project saas             # SaaS dashboard + checkout starter

Each one clones straight into ./<name> (use --path <dir> to pick a different folder), so you're one cd and tdk up away from a running stack. Prefer plain git? Use the links below instead:

Working with multiple stacks

Organize services by stack for selective startup:

Start only the API stack

terminal
tdk up --stack api

Start only specific services

terminal
tdk up api-gateway order-service

Environment configuration

tdk.yml / tdk.production.yml
# development overrides: tdk.yml
env: development
services:
  - name: api-gateway
    port: 3000
    envVars:
      DEBUG: "true"

# production overrides: tdk.production.yml
env: production
services:
  - name: api-gateway
    port: 3000
    envVars:
      DEBUG: "false"

Common patterns

Frontend + backend

two manifests, one system
# frontend service.json
{
  "appName": "web-app",
  "appType": "frontend",
  "port": 5173,
  "featuresEnabled": ["typescript", "vite"],
  "backendName": "api-server",
  "basePath": "/app"
}

# backend service.json
{
  "appName": "api-server",
  "appType": "backend",
  "port": 3000,
  "featuresEnabled": ["typescript", "bun"],
  "envVars": {
    "FRONTEND_URL": "http://localhost:5173"
  }
}

Worker queue

email-worker / service.json
{
  "appName": "email-worker",
  "appType": "worker",
  "featuresEnabled": ["typescript", "bun"],
  "dependsOn": ["redis"],
  "replicas": 3
}

Video transcoding farm: a migrator prepares the queue tables, then three worker replicas drain them. Scale replicas per developer machine.

terminal

tdk up --stack media

Brownfield rescue

The most common real-world case: an existing monorepo with {{ site.data.tdk.brownfield_dirs }} directories and zero manifests. The discovery daemon finds every service, synthesizes missing manifests from directory structure, and the team that was blocked for {{ site.data.tdk.story_weeks }} boots on day one.

terminal
$ tdk up
[discovery] scanned {{ site.data.tdk.brownfield_dirs }} directories · {{ site.data.tdk.brownfield_found }} manifests found
[synthesis] {{ site.data.tdk.brownfield_synth }} manifests synthesized from structure
[generate] {{ site.data.tdk.files_per_service }} files × {{ site.data.tdk.brownfield_dirs }} services → {{ site.data.tdk.brownfield_artifacts }} artifacts written
[health] {{ site.data.tdk.brownfield_healthy }} resources healthy
