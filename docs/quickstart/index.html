Quick Start

From zero to a running local stack in {{ site.data.tdk.quickstart_time }}.

Prerequisites

  • Docker installed
  • Tilt installed
  • Node.js {{ site.data.tdk.prereq_node }} (for frontend tooling)

Installation

Install the latest public binary directly from the TDK CLI release channel. The installer detects Linux, macOS, Intel, and Arm automatically.

One-line install

terminal
curl -fsSL https://tdk-landscape.github.io/install.sh | sh
{{ site.data.tdk.install_npm }}
# run without installing globally
{{ site.data.tdk.install_npx_version }}

# or scaffold a project directly
{{ site.data.tdk.install_npx_project }}
{{ site.data.tdk.install_pnpm }}
{{ site.data.tdk.install_bun }}

Manual download

Download a binary from the public release repo if you prefer to install it yourself.

terminal
curl -fsSL -o tdk https://github.com/tdk-landscape/tdk-cli-releases/releases/latest/download/tdk-linux-amd64
chmod +x tdk
sudo mv tdk /usr/local/bin/tdk

GitHub Releases

Binaries ship with each release from tdk-landscape/tdk-cli-releases. The CLI source can stay private while these release assets stay public.

Docker Compose

Use Docker Compose if you want to try TDK without installing the binary on your host.

terminal
git clone https://github.com/tdk-landscape/tdk-docker-compose-example.git
cd tdk-docker-compose-example
docker compose run --rm tdk tdk --version
docker compose run --rm tdk tdk project --yes

Verify installation

terminal
tdk --version
# tdk-cli v1.0.0

Add your license (optional)

The free engine — docker-compose, Verdaccio, npm, Bun, and everything else in the CLI — never needs a license key. Skip this section if you're on the Free tier.

If you have a Premium or Enterprise key, set it as an environment variable before running tdk up:

terminal
export TDK_LICENSE_KEY=tdk-xxxxxx

Add that line to your shell profile (~/.zshrc or ~/.bashrc) so it persists across sessions, or export it per-project instead. TDK checks the key automatically on the next run and unlocks the premium generators — Playwright E2E, C4 diagrams, structured logging — no separate install step. Each key covers up to {{ site.data.tdk.premium_project_limit }} distinct projects (unlimited on Enterprise). If the key's missing, expired, or unreachable, TDK just keeps going with the free engine — nothing breaks.

Don't have a key yet? Get one — Free costs nothing and needs no key at all; Premium and Enterprise unlock the paid extras.

What actually happens when you run it

Before Tilt touches Docker, tdk checks your environment and tells you exactly what it's doing — no guessing what's happening behind the spinner.

zsh: tdk doctor && tdk up

Don't have Docker or Tilt yet?

tdk up won't just fail silently — it checks both before touching anything, and tells you precisely what's missing and how to fix it:

terminal
$ tdk up

TDK can't start - missing prerequisites:

❌ Docker (or a compatible container runtime) is not running

💡 Suggestions:
   → Start Docker Desktop, then verify with: `docker ps`
   → Or start Colima: `colima start`
   → Or start the Docker service on Linux: `sudo systemctl start docker`
   → Setup guide: https://tdk-landscape.github.io/tdk-website/docs/quickstart/

❌ Tilt CLI is not installed

💡 Suggestions:
   → Install Tilt: `brew install tilt` (macOS)
   → Or download from: https://docs.tilt.dev/install.html
   → Verify with: `tilt version`

Run `tdk doctor` for a full environment check.

Fix what it flags, run tdk doctor to confirm, and you're clear to boot.

Start from a working example

Not sure what a TDK project should look like yet? Skip the blank canvas — tdk project <template> clones a complete, working PSR (Project-Stack-Resource) landscape you can run immediately and learn the structure from.

terminal
# minimal reference stack - start here if you're new to TDK
tdk project example

# or a fuller domain example
tdk project restaurant
tdk project user-management
tdk project erp

cd <cloned-folder>
tdk doctor   # check Docker/Tilt are ready
tdk up       # start the stack

Use --path <dir> to control the destination folder name. See Examples for what each template contains.

Create your first service

Prefer to build from scratch instead? Start with a blank project:

1 — Create a new project

terminal
mkdir my-service
cd my-service
tdk project --yes

2 — Create a backend resource

terminal
tdk resource api --type backend --stack pre-alpha --path services/pre-alpha/api

3 — Add a dependency

TDK/Tilt reads boot order from dependsOn. This example makes api depend on database.

terminal
tdk resource database --type backend --stack pre-alpha --path services/pre-alpha/database
services/pre-alpha/api/service.json
{
  "name": "api",
  "type": "backend",
  "stack": "pre-alpha",
  "port": 4000,
  "dependsOn": ["database"]
}

4 — Inspect service.json

service.json
{
  "name": "api",
  "type": "backend",
  "stack": "pre-alpha",
  "port": 4000,
  "dependsOn": ["database"]
}

5 — Validate configs

terminal
tdk project --check

This validates .tdk/project.json and the generated files in .tdk/.tdk-out/.

6 — Run the stack

terminal
tdk up pre-alpha

Success

Your service is now running locally. Visit http://localhost:3000 — and every new teammate who clones the repo gets the same result in minutes, not weeks.
