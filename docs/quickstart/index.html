Before you run it

TDK needs a container runtime and Tilt. Node.js is only needed when your project has frontend tooling.

  • Docker installed and running
  • Tilt installed
  • Node.js {{ site.data.tdk.prereq_node }} for frontend stacks

Current release platforms: macOS and Linux. Native Windows AMD64 CLI support has merged and its Windows smoke checks pass, but the public release asset and real Windows 11 acceptance run are still pending. Windows instructions below apply once the latest release includes tdk-windows-amd64.exe. WSL2 Ubuntu works as Linux.

Windows 10/11 setup (AMD64)

Use PowerShell on a 64-bit Intel or AMD PC. TDK runs Linux containers through Docker Desktop; Windows containers are not supported. You do not need Administrator access for normal TDK commands.

The installer downloads the latest Windows AMD64 executable. If the latest release does not include tdk-windows-amd64.exe yet, wait for the Windows-enabled CLI release before running the install command.

  1. Install Docker Desktop, switch it to Linux containers, and wait until Docker Desktop says it is running.
  2. Install Tilt for Windows.
  3. Install TDK from PowerShell:
    PowerShell
    irm https://tdk-landscape.github.io/install.ps1 | iex

    Or download and inspect the script before running it:

    PowerShell
    Invoke-WebRequest https://tdk-landscape.github.io/install.ps1 -OutFile install-tdk.ps1
powershell -ExecutionPolicy Bypass -File .\install-tdk.ps1
  4. Close PowerShell and open a new window so the updated PATH is loaded.
  5. Verify TDK and the machine setup:
    PowerShell
    tdk --version
tdk doctor
  6. Scaffold and start the example:
    PowerShell
    tdk project example
cd tdk-example
tdk up
tdk networks

TDK networks prints hostname URLs and numeric 127.0.0.1 URLs. If *.tdk.localhost does not resolve on your Windows setup, use the numeric URL while you fix the hosts-file entries reported by tdk doctor.

Windows problems

  • Docker Desktop is stopped or using Windows containers: start Docker Desktop and wait for “Running”; switch to Linux containers.
  • A planned port is unavailable: TDK plans HTTP ports in 8080–8180, HTTPS ports in 8443–8543, and Postgres ports in 15432–15532. Set TDK_HTTP_PORT, TDK_HTTPS_PORT, or TDK_POSTGRES_PORT to request a specific port; an explicit port fails if it is busy.
  • *.localhost does not resolve: add the two loopback host entries that tdk doctor prints, using an elevated Notepad for the hosts file, or use the numeric URLs from tdk networks.
  • Docker cannot mount the project: in Docker Desktop, open Settings → Resources → File sharing and include the drive containing the project.

Simple setup

Once TDK is installed — pick a method above — this is the whole happy path if you already have Docker running.

terminal
tdk doctor
tdk project example
cd tdk-example
tdk up

Install the CLI

02

Run doctor

03

Use the example

Start from a working PSR landscape instead of inventing the folder structure cold.

04

Boot the stack

tdk up generates the local files and hands orchestration to Tilt.

Verify installation

terminal
tdk --version
# prints the installed version, e.g. 1.3.74

Add your license (if using premium features)

The free tier requires no license key. Premium and Enterprise keys unlock extras such as Verdaccio private registry, DDD scaffolding, Playwright E2E, C4 diagrams, and structured logging.

Have a Premium or Enterprise key?

Export it before running tdk up. TDK checks the key automatically on the next run.

terminal
export TDK_LICENSE_KEY=tdk-xxxxxx

Add that line to ~/.zshrc or ~/.bashrc if you want it to persist. Each key covers up to {{ site.data.tdk.premium_project_limit }} distinct projects, unlimited on Enterprise. If the key is missing, expired, or unreachable, TDK keeps running with the free engine.

What actually happens when you run it

Before Tilt touches Docker, tdk checks your environment and tells you exactly what it's doing — no guessing what's happening behind the spinner.

zsh: tdk doctor && tdk up

Don't have Docker or Tilt yet?

tdk up won't just fail silently — it checks both before touching anything, and tells you precisely what's missing and how to fix it:

terminal
$ tdk up

TDK can't start - missing prerequisites:

❌ Docker (or a compatible container runtime) is not running

💡 Suggestions:
   → Start Docker Desktop, then verify with: `docker ps`
   → Or start Colima: `colima start`
   → Or start the Docker service on Linux: `sudo systemctl start docker`
   → Setup guide: https://tdk-landscape.github.io/tdk-website/docs/quickstart/

❌ Tilt CLI is not installed

💡 Suggestions:
   → Install Tilt: `brew install tilt` (macOS)
   → Or download from: https://docs.tilt.dev/install.html
   → Verify with: `tilt version`

Run `tdk doctor` for a full environment check.

Fix what it flags, run tdk doctor to confirm, and you're clear to boot.

Start from a working example

Not sure what a TDK project should look like yet? Skip the blank canvas. tdk project <template> clones a complete PSR landscape you can run immediately.

terminal
# minimal reference stack - start here if you're new to TDK
tdk project example

# or a fuller domain example
tdk project restaurant
tdk project user-management
tdk project erp

cd <cloned-folder>
tdk doctor   # check Docker/Tilt are ready
tdk up       # start the stack

Use --path <dir> to control the destination folder name. See Examples for what each template contains.

Success

Your stack is now running locally. Every new teammate who clones the repo gets the same result in minutes, not weeks.

Build from scratch

After the example makes sense, create a blank project and add your first backend resource.

terminal
mkdir my-service
cd my-service
tdk project --yes
tdk resource api --type backend --stack shop   # asks you to confirm
tdk project --check
tdk up shop

Add a frontend the same way. It is React by default; pass --framework vue for Vue 3 (TDK CLI 1.3.75 or newer):

terminal
tdk resource web --type frontend --stack shop                   # React + Vite (default)
tdk resource web --type frontend --framework vue --stack shop   # Vue 3 + Vite

TDK validates .tdk/project.json, generates files in .tdk/.tdk-out/, and reads boot order from each resource's dependsOn list.

Manual binary download

Download the binary, its engine files and the checksums yourself. The binary looks for the tdk-cli/ folder next to it.

Windows AMD64 (PowerShell)

Run this after a Windows-enabled CLI release appears in the latest releases:

PowerShell
$dir = "$env:LOCALAPPDATA\tdk\bin"
New-Item -ItemType Directory -Force $dir | Out-Null
$base = "https://github.com/tdk-landscape/tdk-cli-releases/releases/latest/download"
Invoke-WebRequest "$base/tdk-windows-amd64.exe" -OutFile "$dir\tdk.exe"
Invoke-WebRequest "$base/tdk-cli-engine.tar.gz" -OutFile "$dir\tdk-cli-engine.tar.gz"
Invoke-WebRequest "$base/checksums.txt" -OutFile "$dir\checksums.txt"
New-Item -ItemType Directory -Force "$dir\tdk-cli" | Out-Null
tar -xzf "$dir\tdk-cli-engine.tar.gz" -C "$dir\tdk-cli" --strip-components=1

Use install.ps1 instead when possible; it verifies the executable checksum and adds the install folder to your user PATH. Older Windows tar.exe versions may not support --strip-components; the installer handles that fallback.

terminal
os=$(uname -s | tr A-Z a-z); arch=$(uname -m | sed "s/x86_64/amd64/;s/aarch64/arm64/")
base=https://github.com/tdk-landscape/tdk-cli-releases/releases/latest/download
curl -fsSL -O "$base/tdk-$os-$arch" -O "$base/tdk-cli-engine.tar.gz" -O "$base/checksums.txt"
shasum -a 256 -c --ignore-missing checksums.txt
mkdir -p ~/.local/bin/tdk-cli
install -m 755 "tdk-$os-$arch" ~/.local/bin/tdk
tar -xzf tdk-cli-engine.tar.gz -C ~/.local/bin/tdk-cli --strip-components=1

Binaries ship from tdk-landscape/tdk-cli-releases.

Try TDK with Docker Compose

Use Docker Compose if you want to try TDK without installing the binary on your host.

terminal
git clone https://github.com/tdk-landscape/tdk-docker-compose-example.git
cd tdk-docker-compose-example
docker compose run --rm tdk tdk --version
docker compose run --rm tdk tdk project --yes
